1 Đo Lường Token Của Input Mẫu Thực Tế

Hệ thống Issue Triage thực hiện một chu trình hoàn chỉnh gồm 2 round tương tác model: (1) Phân tích issue & đưa ra đề xuất gọi tool get_component_owner; (2) Tiếp nhận kết quả tra cứu và sinh phản hồi tổng hợp cuối cùng kèm phân loại IssueTriage.

Round 1 — Request
System Prompt + User Issue + Tool Schemas
1.220 tokens input
→
Round 1 — Response
Model phát sinh tool_call get_component_owner
140 tokens output
→
App Execution
execute_get_component_owner("payment")
Application nội bộ (0 token)
→
Round 2 — Final Call
Nhận Tool Result & Sinh IssueTriage JSON
1.075 input + 136 output

// Input mẫu thực tế kiểm thử trong BTVN2.ipynb: "Nút thanh toán trả HTTP 500 với mọi thẻ Visa từ 14:30. Hãy triage issue và cho biết team nào cần xử lý."
Prompt Tokens (Input)
2.295
Gồm System Prompt, Function Tools schema, User input và Tool execution result (1.220 + 1.075).
Completion Tokens (Output)
276
Gồm arguments của tool call (140 tokens) và đối tượng IssueTriage JSON phân loại cuối cùng (136 tokens).
Tổng Token / 1 Issue
2.571
Tổng số token tiêu hao cho 1 chu trình xử lý end-to-end hoàn chỉnh của mini-app có tool calling.

💡 Ghi chú kỹ thuật về Context Window & Đo lường Token:

Số lượng token được đo lường chính xác từ thuộc tính response.usage của OpenRouter API (sử dụng tokenizer chuẩn BPE). Nhờ thiết kế prompt template chuẩn chỉ và schema Pydantic chặt chẽ, mỗi issue tiêu tốn khoảng 2.570 tokens cho trọn vẹn 2 round hội thoại và tra cứu tool.

3 Ước Tính Chi Phí Cho 10.000 Issue / Tháng

Với quy mô 10.000 issue/tháng dựa trên số liệu thực nghiệm đo lường từ notebook:

  • Tổng Input Tokens: 10.000 issues × 2.295 tokens = 22.950.000 tokens (22,95M tokens/tháng)
  • Tổng Output Tokens: 10.000 issues × 276 tokens = 2.760.000 tokens (2,76M tokens/tháng)
  • Tổng Token Lưu Chuyển: 25.710.000 tokens (25,71M tokens/tháng)
